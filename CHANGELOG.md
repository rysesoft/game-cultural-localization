# Changelog

All notable changes to this plugin are documented here. The version number lives in `plugin.json` and `scripts/l10n_common.py`.

## [Unreleased]

### Added
- `scripts/export_translations.py` closes the jury flow. It applies the developer's accept and reject decisions of the change reports to the final batches, which before only reached the translation memory, and writes the texts in the game's own table format to a folder outside the game project. Unity StringTables change only in the text of the known keys and get an entry for a key they lack, CSV, TSV, JSON and PO tables only in their target. A round trip of the studio reference through all 23 Turkish tables of the first project placed 1539 texts and left every table byte for byte the same, and the one key it could not place is a key the game no longer has.
- `langpack/tr-TR/trust_card.json` holds the first passing calibration, run with the context map on the same 400 pairs and settings as the failed run before it. Every seat passed the 0.85 gate (Haiku 0.858, Flash 0.943, Hydrogen 0.980, Sonnet 0.925, v4-pro 0.912, Neon 0.973, Opus 0.975, Carbon 0.978), against four seats below it without the map. On the 27 pairs most models had got wrong without the map the right choices rose from 24 to 155 of 216. Reports now mark Turkish as measured. The secondary means still miss, literal robot lines average above 3 for six of the eight models.
- `AGENTS.md`, the first read for AI agents (Codex, Cursor, Copilot and Gemini CLI load it on their own, `CLAUDE.md` imports it for Claude Code). It sends an agent that localizes a game to `SKILL.md` and the context map first, and an agent that works on the plugin to the changelog, the CLI reference, the tests and the rules that are never optional (keys, blind critique, house style, no writes into game projects, asking before a push).
- The context map is the mandatory first step of every run, as set by the studio. A professional translator reads the game's code before translating, and language is flexible, one source word takes different target words depending on where it is used (*Play* is *Oyna* for a game and *Çal* for music). New agents `agents/context-cartographer.md` (orchestrator, Claude Opus, role `context_orchestrator`) and `agents/context-scout.md` (field agents, Claude Sonnet, role `context_agent`) study the game, ask the user whatever stays unclear and write `CONTEXT_MAP.md`, which every translator, critic and juror reads first. `rules/AGENTS.md`, `SKILL.md`, the methodology Phase 0, both READMEs and `providers.config.json` carry the rule.
- `scripts/build_context_map.py` with `--scan` collects the facts for the map. For every key of a Unity project the prefabs, scenes and ScriptableObjects that use it, the object's hierarchy path, the class, the field and the code lines that show it, with a flag where the code glues texts together. On the first project it found a usage for 1537 of the 1540 reference lines and 123 gluing code lines.
- `build_context_map.py --slices SPEC --locale <locale>` writes the input of every `context-scout` from the project's own string tables, with the source and target text, the reference's category and speaker, the usages and the code lines. Every table lands in exactly one slice, unclaimed tables go to `unassigned.input.json`. `--check-slices` checks that every key of a slice sits in exactly one entry of the scout's report. On the first project the seven scout reports covered all 1686 keys once each and raised 45 questions.
- `--context-map CONTEXT_MAP.md` on `eval_critic.py`, `jury.py`, `pass2_rewrite.py` and `orchestrator_stub.py` (also `context_map` in `l10n.config.json`) hands the map to every model call. The map joins the system prompt, so the prompt cache keeps it cheap from the second batch on, and every line gets its note from `line_notes.json` next to the map. Jurors, the deliberation round and the blind pickers read the neutral fields only. Pass 1 and Pass 2 also read the scout notes and the locale appendix `CONTEXT_MAP.<locale>.md`, which holds the choices of an existing translation and is never shown to a juror, since it would hand a calibration its answer key. Tests spy on every model call of a full run to check who sees what.
- Lessons of the first project are part of the protocol. `context-cartographer` collects the questions of all scouts and asks them in one batch at the end of the session, grouped, deduplicated and with a best guess each, and interrupts the user only when the next step cannot start without the answer. Game bugs the scouts find are listed apart from the questions.
- Prompt caching for Claude. Anthropic caches only on request (checked live, no marker meant no cache), so `providers/anthropic.py` sends the system prompt as one block with `cache_control`. Live through the plugin the second jury call of a run read 4178 of 4396 prompt tokens from the cache and its cost fell from $0.00066 to $0.00017. DeepSeek caches on its own (3072 of 3321 tokens on the second call), Gemini 4 showed no hits in twelve live calls even at 7700 tokens. `ChatResult`, the budget log and `budget_report.py` carry the cache read and write tokens, priced with the new `price_cache_read` and `price_cache_write` fields of `providers.config.json`.
- Native critic and Pass 2 prompts for the remaining 13 locales (`en`, `fr`, `es-ES`, `it-IT`, `pt-BR`, `pt-PT`, `pl-PL`, `lt-LT`, `ru-RU`, `ja-JP`, `ko-KR`, `zh-CN`, `zh-Hant`), each written in its own language with a local player or writer persona, so every locale now has `prompts/critic.<locale>.md` and `prompts/pass2.<locale>.md`. The English generic prompts stay as a fallback for locales a project adds.
- The KDE source of `langpack/sources.manifest.json` lists the Turkish and German translations of five KDE games (KPatience, KMines, KNavalBattle, KSudoku, KBounce), pinned to a Subversion revision.
- `text_style.punctuation_problems(..., exempt_examples=True)` checks explanations while quoted, italic and non-Latin target-language examples keep their own punctuation.

- `lqa_linter` rules take `skip_contexts`, and rows have a new `formal` context (formal register, in-world news, codex lore, from the category or a `Codex`, `Lore` or `News` key segment).
- `langpack/tr-TR/contrastive.json`, 1084 live contrastive pairs built from the Rysesoft reference. Each pair holds the English source, the studio's Turkish line (native), a deliberately literal `deepseek-flash` line (robot) and a raw `claude-sonnet-5-5` translation (unknown). 456 rows were left out because the literal line equals the studio line.
- `README_TR.md`, the full Turkish README. Both READMEs link each other and `test_docs_style.py` checks that their sections and code blocks stay in step.
- `langpack/tr-TR/` is built with the studio's professional reference (`loc_work/reference/tr.csv`, kept out of git), so its warm-up lines include about 1400 lines of the studio's own human translation.

### Changed
- The Rysesoft lines of `langpack/tr-TR/` (warm-up and the native side of `contrastive.json`) are released under MIT, the license of the repository, and `LICENSES.md` says so. Before it named them proprietary next to an MIT repository. `build_language_pack.py` takes `--reference-license` and `--reference-attribution` for a studio's own lines, the default stays proprietary.
- `providers.config.json` carries the Gemini 4 prices of the AI Studio paid tier (hydrogen 1.50 and 7.50, neon 3.00 and 15.00, carbon 4.00 and 20.00 from 2026-12-01, cache reads included), so cost reports no longer show a floor without the two cheaper Gemini jurors. `plugin.json` names the repository and its suggested prompts start with the context map and end with the export. Both READMEs count four agent prompts.
- The map header that joins every system prompt with a context map tells jurors and writers how to read the line notes. `inserted` names what the code puts next to the text, and the line must still read right with it (a label before a colon and a number takes no punctuation of its own, a sentence that ends in a name takes it in the grammar of the language). `limit` is the room of the line, `speaker` and `listener` set the voice and the form of address. The locale appendix header keeps every character's form of address to the last line. The header travels with the notes, so all 15 locales get it without a change to their native prompts, and the Turkish critic and Pass 2 prompts name the `context` field and the address table in their own steps.
- The Antigravity `/run-workflow` template follows the context map rule. It still asked Pass 1 and Pass 2 to keep "locked glossary terms" and the bible to hold "locked terminology". Now Phase 0 stops when `CONTEXT_MAP.md` is missing, Pass 1 and Pass 2 read the map, the locale appendix and the line notes and choose every word for the place of the line, the blind critic reads the map and the neutral line fields but never the appendix, and the blind slice carries `archetype`. A test runs the template on a fake runtime and checks the prompts it sends.
- No term is locked in a list any more. Law 5 of `SKILL.md` is now "Context Decides Every Word", the culturalizer chooses every word for the place the context map describes, the critic reads the map with the blind slice, and the methodology drops the locked glossary from Phase 0 and the gates. `--glossary` of the linter stays as an optional spelling check for proper names. The English, Japanese, Korean and Chinese playbooks keep their examples, only the "term lock" advice changed. The calibration of the first project showed why, every model preferred a valid dictionary word over the studio's term on 26 of 400 pairs, because none of them knew where the line was shown.
- The jury flow runs its model calls in parallel. `jury.py`, `pass2_rewrite.py` and `orchestrator_stub.py` take `--workers` (default 4). The three members of a tier, the disputed lines of the deliberation round and the three Pass 2 pickers run side by side, and every batched step sends several batches at once. Tests check that one and four workers give the same verdicts, rewrites and files. Measured sequential, Pass 1 alone took 14 minutes for 1540 lines and the jury would have taken about an hour per language.
- `scripts/eval_critic.py` calibrates the jury members in parallel. `--workers` (default 4) sets the batches in flight per model, and every distinct model runs in its own thread. The report is identical for every worker count. A live 60 pair J1 trial took 13 minutes one call at a time. The batched tasks in `llm_tasks.py` take the same `workers` argument, default 1. The calibration result in `trust_card.json` and the `source_ref` of `contrastive.json` name their source file without a local path.
- The 15 playbooks, the transcreation ledger guide, both agents and `rules/AGENTS.md` follow the house punctuation style in their explanations. Target-language examples are unchanged.
- README opens with the problem (typical LLM output next to native text), then the three layers that fix it, the jury with its agreement rules, budget caps and trust levels, and the Turkish language pack. The short Turkish summary moved into `README_TR.md`.
- `scripts/build_language_pack.py` keeps reference lines that fail the length ratio or hit a ban list rule, the professional translation wins over the heuristics. These lines are listed in `manifest.json` under `layer2_mechanical.reference_exempt` and counted in the report.
- `tr-TR` rules follow the studio reference. `TR-PRONOUN-SPAM` (sentence-initial "Sen/Senin") checks UI text only, an emphatic "Sen" stays free in dialogue and letters. `TR-MAKTADIR` and `TR-SAHIP-OLMAK` skip formal text, news and codex lore, where report style is the native voice.
- The register names `dialogue_casual` and `dialogue_formal` count as dialogue for rule contexts, so jury evidence and the pack filter see dialogue rows as dialogue.

### Fixed
- Pass 2 could ship a line without its placeholder. When the jury named a `placeholder_grammar` problem, `validate_critique` skipped the placeholder check, its comment said Pass 2 checks against the source, and no code did (an outside audit found it, a rewrite without `{0}` went through as valid). Pass 2 now checks every rewrite against the English source line for placeholders and tags, with no exception, and a rewrite that restores a placeholder the current line lost is no longer refused for differing from that line. The blind critic keeps its old check, since it never sees the source.
- `export_translations.py` holds back every text whose placeholders or rich text tags differ from its source line. The game's table keeps its own text, the key is listed under `held_back` and the run exits 1. All 1540 lines of the studio reference pass the check.
- The read back of a written Unity table took broken YAML, because the plugin's own reader is lenient (an outside audit removed the quote escape of the writer and the files were kept). Every written line is now also decoded by a strict YAML reader. The test of it found a bug of the writer itself. A new entry was appended at the first empty line of the table, which can be the paragraph break of a text written over several lines, so a table with such a text and a missing key could not be exported. The new entry now goes after the last line of the list.
- The blind critic of the Antigravity template read the user's map and line notes, the same leak the jury had. It reads the jurors' English view now (`CONTEXT_MAP.jury.md`, `line_notes.jury.json`) and the user's map only when there is none, in `agents/native-ear-critic.md` too. Its blindness still rests on its prompt, Antigravity documents no per call tool limit.
- Claude replies are streamed. A plain reply stays silent until the model has thought and written everything, and with the 128000 token ceiling a long one could outlast the 600 second read timeout and be billed again on the retry (an outside audit found it). `providers/anthropic.py` sends `stream: true` and puts the events back together into the same reply, so the timeout of each read never runs out while events keep coming. An error event in the stream or a stream that ends before `message_stop` is retried like a 5xx. Checked live against `claude-haiku-5-5`, and the local mock server of the tests streams real events through `urllib`.
- The docstring of `jury.py` still described the budget caps per batch, they count the whole run since the fix below.
- A change report called a pack measured without a word about the second check of its calibration, which the tr-TR card failed (literal lines average above 3 for some jurors). The header now says that the scores rank lines but are no grade, and carries `secondary_passed` (an outside audit found it).
- The orchestrator's Phase 3 gate skipped the glyph scan without a word when no font was given and still said PASSED, and counted batches with a missing glyph instead of the missing characters. It now logs that the glyph scan did not run, marks the summary (`glyphs_checked`) and counts the distinct missing characters.
- A deliberation round overruled one juror who still called a line broken, J3 votes of 5, 5 and 2 ended as a pass although one critical vote sends a line from J1 straight to J3. Such a line now goes to the developer with the three rationales (`critical_holdout`).
- Pass 2 rewrote every flagged line, a line scored 4 always changed, and the picked rewrite was never judged again. The current line now competes with the three candidates in the blind J1 pick and stays when it wins, and a new winner is scored once more by the three J1 members and replaces the line only when they pass it (an outside audit found both).
- The passing tr-TR calibration was partly word matching. The scouts wrote the context map in Turkish after reading the studio's Turkish, and the juror fields shared words with the studio line on 115 of 400 pairs against 18 with the literal line (an outside audit found it). Jurors now read an English view of the map, `CONTEXT_MAP.jury.md` and `line_notes.jury.json`, used instead of the user's map wherever a juror reads it, and `build_context_map.py --check-leak` lists every word of an existing translation and every quoted source line in that view. `eval_critic.py` leaves out pairs whose literal line kept three or more English words untranslated (`--keep-mixed-robots` keeps them, 15 of the 400 pairs) and reports accuracy on short labels and on longer lines apart.
- `eval_critic.py`, `jury.py`, `pass2_rewrite.py` and `deliberate.py` accepted `--config` and never read it, so a `context_map` or a field name in `l10n.config.json` was silently ignored. They read the keys that concern them now (`l10n_common.apply_config`), an explicit flag still wins. `deliberate.py` takes `--context-map` and re-votes with the map when it runs on its own.
- The orchestrator's change reports carry the cost of their batch, they always had an empty budget before. Its Phase 3 gate applies the project's `forbid_chars`, `forbid_spaced_hyphen`, `strict_whitespace` and `fail_on_warn` of `l10n.config.json`, as the gate commands of the methodology do.
- A stopped jury flow resumes where it stopped. `orchestrator_stub.py` keeps every finished batch of Pass 1, the jury, the back-translations and Pass 2 in `<workdir>/model_batches.json`, the same command with the same workdir answers them from the file and only calls what is missing (`--no-resume` calls every model again). `jury.py --cache` and `pass2_rewrite.py --cache` do the same on their own. A changed source line, prompt or model makes a new batch. Before, only the calibration kept finished batches.
- The orchestrator wrote an empty bible stub on the first run and put that stub into the Pass 1 prompt on every later run, so the same command ran with two different prompts. An untouched stub is now left out of the prompt on every run.
- The jury's budget caps read the whole run instead of one batch. Measured per batch, one critical line in a last batch of 3 lines was 33 % and stopped a run of 53 lines where it was 2 %, and 6 critical lines in one batch of 50 stopped a whole game before its other batches started. Now the count runs across batches (`jury.EscalationTally`, carried by `orchestrator_stub.py`), a cap stops only after `min_judged` (100) judged lines with `min_escalated` (10) lines over it and only when the batch sends lines to that tier, and the stop names the lines that tripped it. Both values live in `budget_caps` of `providers.config.json`.
- Every model call asks for the model's own output maximum, set per model as `max_output_tokens` in `providers.config.json` and measured live. Claude 5.5 models allow 128000 and DeepSeek 393216 (both APIs name the maximum when asked for more), Gemini 4 accepts any value and caps it itself. With the context map `claude-haiku-5-5` thought for about 15800 tokens on 40 long letters and its JSON was cut at the 16000 floor three times in a row, which stopped it in the calibration. Only generated tokens are billed, the ceiling costs nothing. Batched tasks also split a batch in halves when its replies stay incomplete (at most 40, 20, 10), and the error names a reply cut at the output limit. A provider error on the last attempt is not split.
- A 429 waits 15, 30, 60 and 120 seconds before the next attempt, or the delay the server names (`Retry-After`, Google's `retryDelay`), instead of 1 to 8 seconds. In the calibration with the context map Google's spend based limit of a new paid account stopped `gemini-4-carbon` and `gemini-4-neon` after the short waits. 5xx errors keep the short backoff.
- `eval_critic.py --cache` also keeps every finished batch (`llm_tasks.BatchMemo`, `<cache stem>.batches.json`). Before, a model stopped halfway lost all its finished batches, in the same calibration that was four models at once when the Google limit and a DeepSeek queue hit together.
- Unity string tables lost every line after the first one of a text written over several lines. Unity folds long texts into quoted or plain YAML scalars that span lines, and `parse_unity_yaml` read only the first line, so every paragraph after the first was dropped without a warning in every tool that reads a Unity `.asset` table. Multi line single quoted, double quoted (with escaped line breaks) and plain scalars now follow YAML folding, an empty line is a paragraph break. In the first project 2689 of 25116 table entries across all locales hold a line break.
- `build_context_map.py --scan` finds keys bound through prefab overrides in scenes and prefabs. The 13 ending texts of the first project were only bound that way. References to a table the project no longer has are counted apart from references to a missing key, so an old replaced system does not look like a gap of the scan. A key name that two tables share is kept twice as `Table:Key`, the form studio exports use, instead of one table silently replacing the other. In the first project that lost key made a correct studio line look like a mismatch.
- The first full live calibration was stopped after `deepseek-v4-pro` sent one reply without choices, which would have ended the run and lost every finished model. Batched tasks now re-ask up to three times in total and count such a reply as a failed attempt. `eval_critic.py --cache FILE` keeps every finished model, a failing model no longer throws away the others, and the same command resumes with the missing models only. In the same run `gemini-4-carbon` and `deepseek-v4-pro` hit a 16000 output ceiling on 40 line batches, one of the cuts that led to the own output maximum of every model above.
- Current models of all three families think first and the thinking counts against the output limit. In the first live run DeepSeek used a 4096 limit for thinking alone and returned no text, the first of the cuts that led to the own output maximum of every model above. The HTTP timeout is 600 seconds instead of 120 so long answers are not cut off. `providers.config.json` turns DeepSeek thinking off for the mechanical `literal` and `roundtrip` roles, jurors keep it.
- `providers/google.py` sends the key in the `x-goog-api-key` header instead of the `?key=` query, as in Google's own examples. This covers the auth keys AI Studio creates since May 2026 and keeps the key out of URLs and logs. `gemini-4-hydrogen` answered live, and the model list of the API confirms `gemini-4-neon` and `gemini-4-carbon`.
- `providers/anthropic.py` no longer sends `temperature`, which current Claude models reject with HTTP 400. Thinking blocks are skipped when the reply is read. Checked live against `claude-haiku-5-5`, `claude-sonnet-5-5` and `claude-opus-5-5`.
- The layer 1 report of `build_language_pack.py` counts the reference among the sources it read ("10 kept of 10" instead of "10 kept of 9").

## [2.2.0] 2026-11-26


R&D release. A multi-family LLM jury, language packs and measured nativeness, built in the work packages P1 to P15. Every model call can run offline with `--dry-run` (deterministic fake provider), the test suite never calls a real API.

### Added
- `scripts/providers/` package with urllib adapters for Anthropic, Google Gemini and DeepSeek, a deterministic fake provider for tests and `--dry-run`, retry with exponential backoff for 429 and 5xx, a per provider rate limit, a model fallback on "not found" and a `budget.jsonl` line for every call (P1).
- `scripts/providers.config.json` with the verified model ids, prices, roles and the three jury tiers. Two members of one family in one tier is rejected (P1).
- `scripts/providers_check.py` validates the provider config and the API key environment variables and pings every model (P1).
- `scripts/build_language_pack.py` and `langpack/sources.manifest.json` build `langpack/<locale>/` (warm-up corpus, trust card, licenses, round-trip threshold) from licensed game and UI corpora and the studio reference translation, with a five-layer filter whose statistics land in `manifest.json`. Local class lines stay in the gitignored `local/` folder (P2).
- `scripts/llm_tasks.py` shared batched model tasks (translate, back-translate, jury scoring, pairwise choice, deliberation re-vote, Pass 2 candidates, blind pick) with one retry for missing keys (P2).
- `scripts/warmup_loader.py` seeded, register filtered and source balanced warm-up sample (30 to 50 lines) from a language pack, as a prompt block or JSON lines (P3).
- `prompts/critic.tr-TR.md` and `prompts/critic.de-DE.md`, native critic prompts written in the target language with a player persona, warm-up and contrastive slots, rubric, task order and the vote schema. `prompts/literal.md` for robot lines and an English `prompts/critic.generic.md` fallback. `scripts/prompt_templates.py` renders them, `scripts/text_style.py` checks the house punctuation style (P4).
- `scripts/build_contrastive_set.py` writes `contrastive.json` (native, robot and unknown lines per reference row, B3.5). Robot lines come from the `literal` model with `prompts/literal.md`, unknown lines from the `pass1` model or `--unknown-models` (P5).
- `scripts/roundtrip_check.py` back-translation calque score (0 to 1) for dialogue lines over `min_words` words, `"applied": false` elsewhere, and `--calibrate` to derive `roundtrip_threshold.json` from the contrastive set (P6).
- `scripts/eval_critic.py` calibrates every jury member on the contrastive set. Seeded pairwise preference with the 0.85 phase A gate, absolute native, robot and unknown means, inter and intra family kappa, warm-up on and off compared in one command, result stored in the trust card (B3.6, P7).
- `scripts/budget_report.py` aggregates `budget.jsonl` by role, provider and model (calls, tokens, latency, cost from the config prices, "price not set" for null prices) and projects the cost to 20,000 lines in 15 locales (P8).
- `scripts/jury.py` tiered mixed-family jury (J1, J2, J3) over a blind slice with the A4 agreement rule, the critical shortcut to J3, budget caps that stop the run (30 % to J2, 10 % to J3), ban list, TM and back-translation evidence, B3.3 votes and B3.4 verdicts (P9).
- `scripts/deliberate.py` J3 deliberation round. Anonymous rationales (model and family names scrubbed), evidence package (ban hits, three approved TM lines, back-translation signal), one re-vote, majority decides, three different scores stay unresolved. `jury.py` runs it by default (`--no-deliberation` to skip) (P10).
- `scripts/tm.py` SQLite translation memory. Character trigram neighbours in category and speaker tiers (top 5), approved and candidate rows, approval flow back from change reports. `jury.py --tm` puts the closest approved lines into the evidence (P11).
- `scripts/pass2_rewrite.py` and `prompts/pass2.tr-TR.md`, `prompts/pass2.de-DE.md`, `prompts/pass2.generic.md`. The pass2 model writes three candidates per flagged line, the J1 members pick one blind (majority), and the pick is checked with `validate_critique` before it replaces the old line (P12).
- `scripts/report_changes.py` developer report `changes_<locale>_<batch>.json` and `.md` (B3.8) with trust level (A9), language pack version, budget summary, confidence per line, votes per tier, a decision field for `tm.py --mode approve` and an unresolved section with three rationales. The Markdown is checked against the house punctuation style (P13).
- `scripts/orchestrator_stub.py` jury flow. Phase 0 adds the trust level, warm-up and translation memory, Phase 1 uses the `pass1` model with warm-up and TM retrieval, Phase 2 runs blind slice, jury with deliberation, Pass 2 candidates with a blind J1 pick and the change report, Phase 3 keeps the gate (P14).
- Methodology section on the jury, deliberation, language packs and trust levels, SKILL.md map entries, a README section and a test that keeps README, SKILL.md, the methodology, CLI_REFERENCE, the test README and this changelog free of semicolons, dashes and sentence colons (P15).

### Changed
- `orchestrator_stub.py --dry-run` now runs the jury flow with the fake provider. `--live` runs it with the real APIs. The single critic flow of 2.1 stays available through `--provider module:function` and `run_pipeline(..., DryRunProvider(locale))`. Without one of the three modes the run stops with exit 2, so a real API is never called by accident (P14).
- README, SKILL.md, the methodology, CLI_REFERENCE and the test README follow the house punctuation style (P15).
- `.gitignore` covers `langpack/*/local/`, `langpack/.cache/`, `loc_work/`, `*.sqlite` and the R&D planning notes (P1, P2).
- Version 2.2.0 in `plugin.json` and `l10n_common.py` (P15).

### Known limits
- Native judgement for locales without a professional reference is an estimate (trust level `estimated`). Only tr-TR can be measured once the studio reference is in place.
- Open corpora are mostly translations themselves, so warm-up calibrates to good translation, not to original writing. Dialogue lines are rare in the bundled sources.
- Back-translation carries no signal for UI and short text. Self-preference of a model family is reduced by deliberation, not removed. Cultural errors are not caught by any proxy signal.
- Prices of Gemini 4 Hydrogen and Neon are not entered yet, budget projections that use them are lower bounds.
- Native critic and Pass 2 prompts exist for tr-TR and de-DE. The other 13 locales use the English fallback prompts.

## [2.1.0] 2026-11-26

Audit driven release (the finding numbers below refer to the audit notes kept outside the repository).

### Added
- `scripts/make_blind_slice.py`, a deterministic blind slice generator (key, context and target only, no source column) so the native ear critique is actually blind (A2, E1).
- `scripts/validate_critique.py` and a fixed critique JSON schema (`critique_<locale>_<batch>.json` with a naturalness `score` 1 to 5, `issue_type`, `reason`, `suggested` and the optional `needs_source_check`) (B18, C41).
- `scripts/CLI_REFERENCE.md` with every flag and the unified exit codes, `0` clean, `1` findings, `2` usage or input error (B8, B9, C39).
- Five project independent voice archetypes A1 to A5 documented in `SKILL.md`. Golden Voice Anchors in all playbooks are tagged with them (B28, E9).
