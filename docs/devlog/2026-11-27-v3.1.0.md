# Devlog 3.1.0. Thirteen languages in one day, and what they cost

27 November 2026. [Türkçe](./2026-11-27-v3.1.0_TR.md)

On release day of SpaceShip Mechanic Simulator, a Rysesoft game, the plugin reviewed or translated all thirteen of its new languages in one working day. Russian and German had machine translations in the game, the jury reviewed them and Pass 2 corrected the lines it flagged. Spanish, French, Italian, Japanese, Korean, Lithuanian, Polish, Brazilian and European Portuguese and both Chinese scripts were translated from English and went through the same jury. No professional translator took part, so every language is reported as estimated. Version 3.1.0 is what that day taught us.

## The day in numbers

| | |
|---|---|
| Languages | 13, each with 1666 text keys |
| Lines the jury passed on the first try | 59 to 72 percent per language |
| Lines Pass 2 rewrote | 342 (German) to 519 (European Portuguese) |
| API cost | 452.98 USD for all 13, from 22.71 (German review) to 54.41 (Lithuanian) |
| Requests | one provider alone saw 2696 requests and 69 million tokens in the day |

Lithuanian was the hardest and the most expensive language. Its jurors disagreed more often, so more lines climbed to the top tier, where Claude Opus and Gemini Carbon judge, and that tier alone cost about 29 USD of its 54.

## What 3.1.0 changes

**Batch mode.** `--batch` sends the calls of Anthropic and Google models through their batch APIs, which bill every token at half the price. The tools do not change. The calls a step sends together become one job per model, the job is polled and every call gets its own reply. A reply comes when the job ends, usually within an hour, so batch mode is for runs that can wait. DeepSeek has no batch API and stays real time. A live test sent two requests to each vendor. Each pair went out as one job, Anthropic answered in 95 seconds and Google in 115. The same test showed that Gemini refuses a batch request that asks for more than 65536 output tokens, which no document mentioned, so batch requests now stay under it.

**Fewer, larger calls.** Every call resends the system prompt, which holds the context map, the warm-up lines and the few-shots, up to about 48000 tokens for Pass 1. Batches now carry up to 100 rows for Pass 1 and the jury (30 and 40 before) and 30 for Pass 2 (10 before), with a character budget so a hundred long letters never land in one call.

**Cache priming.** When a step sends several batches at once, the first one now goes alone. Before, eight parallel first calls each paid to write the same prompt to the cache, because none of them could read what the others were still writing.

**Batched deliberation.** When the top tier disagrees, each juror votes again after reading the other two. That used to be one request per line and juror, now each juror re-votes all disputed lines in a few calls.

**A parallel recheck.** The three jurors who confirm a Pass 2 rewrite now score side by side. One after another, the Lithuanian recheck waited more than 20 minutes.

**Requests in the budget report.** The report puts the request count next to the cost, per source line too, so a run that sends too many is seen at once.

## What the day taught us

**Read the font chain the way the engine does.** Our first control round said 211 Simplified Chinese lines would show boxes, because the game's static Chinese atlas lacks 147 characters. It was wrong. That atlas has its own fallback font, a dynamic atlas that covers every character, and TextMesh Pro searches it first. The new glyph scanner follows every fallback table, and it caught our mistake. The same scan found a real problem. Typographic marks such as ’ and … are missing from the game's Latin font and fell back to a Chinese font, where they are full width, so French "l’atelier" would have shown a wide gap. The scanner now reports such a fallback.

**Not every Unity table holds text.** The game keeps its decal textures in an AssetTable whose entries are texture GUIDs. The pipeline translated them and wrote the word Hangar in place of a GUID in five languages. The exporter now leaves such tables out.

**The gate must not cry wolf.** On the final texts the automated gate raised 84 errors. Every one but a Japanese style note was a correct line, among them 62 Korean particles after closing tags and 17 Traditional Chinese names written with 里. Six rules are narrowed, and the gate drops to one finding.

**One note per key.** The context map once described a whole group of warning keys with one sentence. For one of them the trigger was wrong, and all three jurors criticised a correct Russian line from that wrong premise. Before we accepted any undecided line we checked its own code path, and two of our own proposals fell. The context scan now traces every loaded key to the places that show it, and marks the ones that are loaded but never shown.

**A jury that cannot agree still has an answer.** Across the thirteen languages the jury could not agree on 69 lines. For 57 of them a rewrite had already passed the recheck. We compared each with the game's code and with the rest of its language and applied 47. We kept the old line in 10, where the rewrite would break consistency (a region name that 12 other lines use, a form of address the other contracts do not) or where the code proved the old line right, and in the 12 lines whose rewrite the recheck had not confirmed.
